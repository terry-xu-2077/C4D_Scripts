# C4D Scripts

用于集中存放 Cinema 4D 相关脚本、插件与 Python 标签代码。

## 开发基准

本项目所有开发默认以 **Cinema 4D 2025 版 API** 为基准。

- 脚本、插件与 Python Tag 默认优先兼容 Cinema 4D 2025。
- API、常量、对象类型、事件与行为均以 Cinema 4D 2025 的实现为主要参考。
- 如需兼容其他 Cinema 4D 版本，应在具体任务中单独说明，并尽量避免影响 2025 版的默认行为。

## 仓库结构

本仓库按任务类型进行归档。目前至少分为以下三类：

```text
C4D_Scripts/
├─ scripts/       # Cinema 4D 内直接运行的脚本
├─ plugins/       # Cinema 4D 插件
├─ python_tags/   # Cinema 4D Python 标签脚本
└─ README.md
```

### `scripts/`

存放可在 Cinema 4D 脚本管理器中直接运行的脚本，例如对象处理、批量操作、动画辅助、建模辅助等工具。

### `plugins/`

存放需要以 Cinema 4D 插件形式安装和运行的功能，包括具有独立界面、持续状态或更复杂集成功能的工具。

### `python_tags/`

存放用于 Cinema 4D Python Tag 的代码，适合依附于场景对象、随场景运行或根据对象状态实时执行的逻辑。

## 脚本索引

### `scripts/MoGraph_索引跟随.py`

用于从 MoGraph 生成器中提取指定索引对象的最终世界变换，并驱动一个普通场景对象进行跟随。

当前支持：

- 分裂对象（Fracture）
- 克隆对象（Cloner）
- 矩阵对象（Matrix）

运行脚本后，会在当前选中的 MoGraph 对象上自动创建 Python Tag，并生成以下用户数据：

- **对象索引**：指定要读取的 MoGraph 元素索引。
- **被链接对象**：指定接收世界位置、旋转和缩放的目标对象。
- **过渡**：在目标对象“当前帧自身动画计算结果”与指定 MoGraph 元素最终世界变换之间进行插值。

过渡语义：

- **0%**：完全保留被链接对象当前帧自己的动画结果。
- **1%–99%**：从该帧自身动画状态逐步过渡到 MoGraph 指定元素。
- **100%**：完全跟随指定 MoGraph 元素的最终世界变换。

为了避免 Python Tag 在同一帧重复执行时读取到自己上一轮写回的矩阵，脚本会按当前时间点缓存一次目标对象自身动画计算后的世界矩阵，并以此作为本帧的过渡基准。因此，被链接对象即使本身存在位置、旋转、缩放动画，也可以正常与 MoGraph 跟随结果进行混合。

脚本读取经过运动图形效果器计算后的 `MODATA_MATRIX`，并转换为世界矩阵，因此可跟随效果器处理后的最终位置、旋转和缩放结果。

## 归档规则

新增内容时，根据实际用途放入对应目录：

- 普通 C4D 脚本 → `scripts/`
- C4D 插件 → `plugins/`
- Python 标签代码 → `python_tags/`

后续如出现新的明确任务类型，可继续增加新的一级目录，例如资源、示例、文档等；不强行塞入现有三类。

## README 维护规则

以后每次新增一个可独立使用的脚本、插件或 Python Tag，都要同步更新本 README，为其补充一条简要说明，至少包括：

- 文件路径或名称
- 主要用途
- 适用对象或使用场景
- 关键功能或主要参数

README 作为本仓库的功能索引持续维护，避免只存代码而没有对应说明。
